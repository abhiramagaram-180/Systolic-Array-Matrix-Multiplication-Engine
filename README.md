# 4x4 Systolic Array Matrix Multiplier

This project is a Verilog-2001 design of a 4x4 systolic array that multiplies two 4x4 matrices of 8-bit unsigned numbers (C = A x B). It is output-stationary: each of the 16 processing elements (PEs) keeps one element of C in its own 20-bit accumulator, while A values flow to the right and B values flow down. The Verilog design is the **verified reference model**: a self-checking testbench compares it against a software reference for several hardcoded and random cases. The same design is then redrawn by hand in **Logisim**, and its results are checked against the same expected values.

## Folder layout

```

tb/         testbench for rtl/ (tb_top.v)
rtl_gate/   GATE-LEVEL (structural) Verilog: fa, adder_n, mult_4x4, dff, reg_n, pe, counter4, ...

scripts/    run.sh (behavioural), run_gate.sh and check_gate_only.py (gate-level)
logisim/    behavioural Logisim circuit (systolic_4x4_auto.circ) + ROM images (make_rom.py),
            gate-level Logisim circuit (systolic_gate_level.circ), make_cases_gate.py, gate_generator/
docs/       spec, explanations, hand trace, Logisim build guide, gate-level design, viva notes, report draft
README.md   this file
```

## How to run the Verilog reference model

```bash
bash scripts/run.sh      # compile + simulate, prints PASS/FAIL per test
gtkwave dump.vcd         # view the waveform
```

`run.sh` exits with a non-zero status if any test prints FAIL.

## Two versions of the implementation

My professor has not yet confirmed whether the project should be **behavioural** or **structural / gate-level**, so the repository contains both. They are independent: nothing in the behavioural version was changed to add the gate-level one.

| | Behavioural version | Gate-level (structural) version |
|---|---|---|
| Idea | Uses operators and library blocks: `+`, `*`, `==`, `always`; Logisim Adder, Multiplier, Register, Counter, Comparator, ROM | Uses only AND / OR / XOR / NOT gates and D flip-flops, joined by module instances (Verilog) or subcircuits (Logisim) |
| Data | 8-bit unsigned inputs, 20-bit accumulators | 4-bit unsigned inputs (0..15), 10-bit accumulators (8 / 20 bits with one setting) |
| Verilog | `rtl/` and `tb/tb_top.v` | `rtl_gate/` and `tb_gate/tb_top.v` |
| Run the Verilog | `bash scripts/run.sh` | `bash scripts/run_gate.sh` (also `nand`, `w8` options) |
| Logisim | `logisim/systolic_4x4_auto.circ` (circuit `main_4X4_auto`; ROM images from `make_rom.py`) | `logisim/systolic_gate_level.circ` (circuit `main` and one wrapper per test case) |
| Logisim helper scripts | `logisim/make_rom.py` | `logisim/make_cases_gate.py` (expected results) and `logisim/gate_generator/` (generator, net checker, headless verification) |
| Explanation | `docs/control_explained.md`, `docs/pe_and_array_explained.md`, `docs/control_logic_added.md` | `docs/gate_level_design.md` (bottom-up, gate counts, 10 viva questions) |
| Size | not defined (library blocks) | 2674 two-input gates + 341 flip-flops |

The architecture is the same in both: 4x4 output-stationary array, A flows right, B flows down, PE(i,j) sees A[i][k] and B[k][j] at t = i + j + k, row i and column j are delayed by i and j register stages, 10-cycle latency, and the control `clear = Start AND NOT run`, `busy = run AND NOT done`, `done` when t = 10, a new Start accepted one tick after `done`.

How to run the gate-level version:

```bash
bash scripts/run_gate.sh                 # structural Verilog (Icarus Verilog 0.9.7): unit + system tests
python scripts/check_gate_only.py        # checks rtl_gate/ has no behavioural code except dff.v
python logisim/make_cases_gate.py        # prints the test matrices and the expected results
python logisim/gate_generator/check_circuit.py        # net checker (shorts, undriven inputs, unconnected pins)
python logisim/gate_generator/verify_gate_level.py    # headless Logisim simulation, bottom-up (needs Logisim-evolution)
```

## Logisim version of the design

The circuit is drawn by hand in Logisim following `docs/logisim_build_guide.md` (no `.circ` file is generated by the scripts).

```bash
python logisim/make_rom.py 4 hand_picked   # one case: writes logisim/roms/hand_picked/*.hex
python logisim/make_rom.py all             # every case, and rewrites logisim/test_cases.md
```

The script prints the expected C (decimal and hex) and the cycle-by-cycle table of what enters each row and column after the skew. Load the images into the ROMs (right-click a ROM, Load Image), run the circuit and compare the 16 probes with the expected C.

### Verilog module to Logisim part

| Verilog | Logisim part |
|---------|--------------|
| `pe.v` | `PE` subcircuit: 2 Bit Extenders (8 to 20 bits), 20-bit Multiplier, 20-bit Adder, 20-bit `acc` Register, two 8-bit Registers for `a_out` and `b_out` |
| `systolic_array.v` | 4x4 grid of `PE` subcircuits in `main`; `a_link` and `b_link` are plain wires between neighbours |
| `control.v` state and counter | `run` Register, 4-bit Counter `t`, Comparator `t = 10` (this is `done`), and 5 gates |
| `control.v` feeder (`A[i][t-i]`, `B[t-j][j]`) | 8 ROMs addressed by `t` (unskewed data) plus i delay Registers on row i and j on column j |
| `A_flat`, `B_flat` | ROM contents (loaded from `logisim/roms/<case>/`) |
| `clear` | `Start AND NOT run`, wired to the Clear pin of every Register and the Counter |
| `done` | Comparator output (`t` equals 10) |
| `top.v` | The `main` circuit |
| `tb_top.v` | You, with `make_rom.py` and `test_cases.md`: load a case, press Start, tick, compare probes |
